## cloudflare tunnel内网穿透

### 一、准备工作

#### 1.前情提要

- [x] 适用于无可用公网ip时（设备可上网）
- [x] 仅适用于网页浏览，可接受信息安全仅靠其隐私政策保证
- [x] 2026新用户必须添加支付方式

#### 2.创建隧道拿令牌

- 登录cloudflare网页

- 左侧侧边栏点击`联网`下拉，再选择`tunnel`，到达tunnel页面

- 创建隧道

  - 隧道名称：web

  - 隧道id：xxxx（默认即可）

  - 选择docker，复制安装命令，先试连接一次，保留该隧道：

    ```
    docker run cloudflare/cloudflared:latest tunnel --no-autoupdate run --token eyJxxx...
    ```

    > `eyJxxx...`仅为示例令牌，按照实际token令牌为准，后文亦如此

#### 3.清理DNS记录

- 在此之前使用ddns的方式还残留有dns记录，先删除对应的`web.example.test`记录

  > `web.example.test`域名仅为示例，具体以自己实际域名为准，后文亦如此

### 二、配置

#### 1.隧道配置

- 点击已创建的隧道`web`进行配置

- 上方点击`路由`更换到路由页

  - 添加路由，选择`已发布的应用程序`

  - 子域名填写`web`

  - 域填写已经托管的`example.test`

  - 服务URL填写`http://fastapi:8000`

    > url末尾不要`/`，否则将会提示无效

#### 2.服务配置

`.env`更改配置

```properties
# FastAPI端口
FASTAPI_PORT=8000
# 域名
WEB_DOMAIN=web.example.test
# cloudflare tunnel token
CF_TUNNEL_TOKEN=eyJxxx...
```

`docker-compose.yml`更改配置

```yaml
services:
  fastapi:
    build: .
    container_name: fastapi
    restart: unless-stopped
    volumes:
      - ./app:/app
    command: uvicorn main:app --host 0.0.0.0 --port 8000 --reload
    networks: [test]

  # Cloudflare Tunnel 内网穿透：公网不可达时（无公网IP）用隧道远程访问。
  cloudflared:
    image: cloudflare/cloudflared:latest
    container_name: cloudflared
    restart: unless-stopped
    command: tunnel --no-autoupdate run
    environment:
      - TUNNEL_TOKEN=${CF_TUNNEL_TOKEN:-}
    networks: [test]
    depends_on:
      - fastapi

networks:
  test:
```

> [!NOTE]
>
> 转为tunnel内网穿透就不需要自行配置反向代理和证书管理了。nginx提供的TLS和路由，以及acme提供的证书管理，都被`Cloudflare边缘`+`隧道ingress`接管了

#### 3.启动服务

```bash
docker compose up -d --build
```

#### 4.验证

使用浏览器访问：https://web.example.test

如果可以正常访问，即是内网穿透成功（cloudflared日志以及cloudflare的管理面板亦可观察到）





*写在最后*

使用cloudflare tunnel内网穿透的确方便，但是相应的大陆访问效果相当一般，原因众多：

```
大陆访客 ──► CF边缘(anycast) ──► CF内部骨干 ──► 有隧道的落地机房 ──► cloudflared ──► 源站
```

- GFW干扰：QUIC走UDP 7844常被限速/丢包，隧道被迫降级或反复重连，表现为卡顿、断流。
- CF边缘就近但路径并非最优：三大运营商跨境路由本就不优，晚高峰国际出口拥塞、丢包、抖动严重。
- cloudflared自选偏远落地机房：大陆用户经常被分到SJC/LAX等美西节点，绕远路，并且无法指定，亦会导致延迟高。
- 大陆CF节点不对免费版开放：大陆也有CF节点，但是只对企业版开放，免费版享受不到。

优选ip？效果有限：

- 优选的本质是”改客户端把域名解析到更快的 CF IP“，但这种方式只对”控制得了 DNS/hosts 的设备“生效，公开访客用不上
