# 前端搜索框设计笔记

> 搜索框不仅是输入控件，还涉及查询语义、交互反馈、异步请求、键盘导航、可访问性、URL 状态同步、安全与性能。设计前应先区分搜索框的工作模式。

## 一、四种搜索模式

| 模式 | 典型场景 | 核心行为 |
|---|---|---|
| 过滤模式（Filter Mode） | 表格筛选、列表筛选 | 输入后过滤数据集，结果数量变化 |
| 定位模式（Find Mode） | 仅展示表格中的查找/跳转 | 不过滤数据，只高亮匹配项并上下键跳转 |
| 建议模式（Typeahead / Autocomplete） | 全局搜索、地址搜索 | 展示搜索建议、历史词、热门词 |
| 命令面板（Command Palette） | 全局快捷入口 | 搜索命令、页面、资源并键盘执行 |

> “表格类搜索增加高亮和上下键跳转”属于定位模式（Find Mode），应与过滤模式（Filter Mode）明确区分。

## 二、输入与查询语义

- 标签（Label）与占位符（Placeholder）分离：后者只是提示文本，不能替代可访问名称。
- 输入规范化（Normalization）：`trim` 去首尾空格、大小写折叠、全角/半角转换、Unicode 字符编码统一、重音符号处理。
- 多关键词搜索（Multi-keyword Search）：按空格分词，明确 AND（同时包含）/ OR（任一包含）语义。
- 支持短语搜索 `"exact phrase"`、排除词 `-exclude` 等高级查询语义。
- 模糊搜索（Fuzzy Search）：前缀匹配、编辑距离、拼写纠错、拼音匹配、同义词匹配。
- 最小搜索长度（Min Length）：达到一定字符数后才触发搜索，避免无效请求。
- 空查询策略（Empty Query Policy）：空输入时展示全量、展示初始态，还是禁止搜索，需要明确。
- 输入法组合事件（IME Composition）：监听 `compositionstart` / `compositionend`，中文输入法组合期间不触发自动搜索。
- 回车语义分层（Enter Submit Semantics）：
  - 无建议列表时，`Enter` 提交搜索；
  - 有建议列表时，`Enter` 选中当前建议；
  - 定位模式（Find Mode）下，`Enter` 跳转下一个匹配项；
  - 可配合 `Shift+Enter` 跳转上一个匹配项。
- 移动端输入属性：`enterkeyhint="search"` 让回车键显示为搜索、`inputmode="search"` 指定搜索输入模式，以及 `autocomplete`、`spellcheck`、`autocorrect`、`autocapitalize` 按场景配置。

## 三、交互与键盘行为

- 一键清空（Clear Button）：
  - 仅在有输入时显示；
  - 提供 `aria-label`；
  - 清空后焦点回到输入框；
  - 同步重置分页、筛选、高亮当前项和建议列表。
- 快捷键打开搜索：
  - 常见为 `Cmd/Ctrl+K` 或 `/`；
  - `Esc` 关闭建议面板或清空输入；
  - 避免与浏览器/系统快捷键冲突；
  - 使用 `<kbd>` 展示快捷键提示。
- 焦点管理（Focus Management）：
  - 快捷键打开后自动聚焦输入框；
  - 关闭搜索面板后焦点返回触发元素；
  - 键盘焦点用 `:focus-visible` 保持可见。
- 建议列表键盘导航：
  - `ArrowDown` / `ArrowUp` 移动当前项；
  - `Enter` 选择；
  - `Esc` 关闭；
  - 明确循环还是边界停靠；
  - 用 `aria-activedescendant` 管理虚拟焦点。
- 加载与禁用状态：提交搜索时按钮进入 Loading 状态，请求中避免重复提交。
- 点击外部关闭：建议面板支持点击外部关闭，但不要误清空已提交查询。

## 四、自动搜索与异步请求

- 防抖（Debounce）：输入搜索常用 200–400ms；区分 leading（首次触发）/ trailing（停止后触发）；输入法组合（IME）期间暂停触发。
- 防抖与节流区分：输入搜索优先防抖；滚动、窗口尺寸变化才考虑节流。
- 请求竞态（Race Condition）：用 `AbortController` 取消旧请求，或用递增 `requestId` 丢弃过期响应，避免后发先至导致结果错乱。
- 结果缓存与预取：memoization（记忆化缓存）、stale-while-revalidate（先返回旧缓存再后台更新）、热门查询预取。
- 加载反馈：输入即时反馈，结果区使用 Loading Skeleton（加载骨架屏），避免闪烁。
- 错误态（Error State）：请求失败展示重试入口，不要与“无结果”混淆。

## 五、搜索建议与预测

- 建议来源：历史搜索、热门搜索、推荐词、实体补全、拼写纠错。
- 建议项高亮：高亮匹配片段时必须做 HTML 转义和正则转义。
- 建议请求竞态：同样需要取消或 `requestId` 校验。
- 建议选择行为：选择建议后是立即搜索、填入输入框，还是进入详情页，需要明确。
- 空建议态：无建议时展示默认提示或隐藏面板。
- 隐私与持久化：搜索历史存 `localStorage` 时提供清空入口，注意敏感信息。

## 六、结果展示与数量统计

- 结果计数（Result Count）：
  - 展示 `total`（总数）和 `filteredCount`（过滤后数量）；
  - 定位模式展示 `current / total matches`（当前匹配序号 / 总匹配数）；
  - 数量变化用 `aria-live="polite"` 播报。
- 空状态（Empty State）：区分初始态、无结果、加载中、请求失败。
- 分页与排序重置：查询变化后重置页码；排序、筛选、查询条件组合管理。
- 高亮匹配（Match Highlighting）：
  - 用 `<mark>` 或受控高亮组件；
  - 必须转义 HTML，防止 XSS（跨站脚本攻击）；
  - 正则特殊字符必须转义；
  - 多关键词分别高亮。
- 定位模式导航：
  - `Enter` / `ArrowDown` 下一个匹配；
  - `Shift+Enter` / `ArrowUp` 上一个匹配；
  - 明确 wrap-around（循环）还是边界停靠；
  - 当前匹配用 `scrollIntoView({ block: "center" })` 滚动到视口中间；
  - 维护 `activeMatchIndex` 与 `aria-activedescendant`。

## 七、状态管理与 URL 同步

- 搜索状态机：`idle`（空闲）→ `typing`（输入中）→ `loading`（加载中）→ `success`（成功）/ `empty`（空结果）/ `error`（失败）。
- 状态分层：
  - `inputValue`（输入框即时值）；
  - `debouncedQuery`（防抖后的查询）；
  - `committedQuery`（已提交查询）；
  - `suggestions`（建议列表）、`results`（结果）、`loading`（加载中）、`error`（错误）、`activeIndex`（当前选中索引）。
- URL 查询参数同步：`q`、`page`、`sort`、`filters` 写入 URL；支持深链接与前进/后退。
- `replaceState`（替换当前历史记录）与 `pushState`（新增历史记录）：输入过程用 replace，提交搜索时用 push，避免历史记录爆炸。
- 可恢复性：刷新页面后恢复查询条件；清空后恢复全量展示。

## 八、可访问性（Accessibility）

- 使用 `role="search"` 或 `<search>` 语义区域。
- 输入框有可访问名称：`label` / `aria-label` / `aria-labelledby`。
- 建议列表使用 `combobox`（组合框）+ `listbox`（列表框）+ `option`（选项）模式：
  - `aria-expanded`（展开状态）、`aria-controls`（控制关系）、`aria-activedescendant`（当前活动选项）；
  - 键盘可完成打开、移动、选择、关闭。
- 结果数量与状态变化用 `aria-live="polite"` 播报。
- 清空按钮、搜索按钮有明确 `aria-label`。
- 全键盘可操作，焦点可见，焦点顺序合理。
- 占位符不作为唯一标签；颜色对比度满足 WCAG（Web 内容无障碍指南）。

## 九、安全与国际化

- XSS 防护：高亮、建议词、搜索历史渲染时转义 HTML。
- 正则转义：用户输入用于高亮正则时必须 escape。
- 服务端安全：参数化查询、速率限制（Rate Limiting）、权限过滤、敏感词策略。
- 国际化（I18N）：
  - Unicode 字符编码统一、大小写折叠、重音处理；
  - CJK（中日韩文字）分词与拼音搜索；
  - 全角/半角、简繁转换、不同 locale（语言区域）行为。
- 权限过滤：搜索结果必须过滤无权限数据，不能只在前端隐藏。

## 十、性能与架构

- 客户端搜索 vs 服务端搜索：
  - 小数据集可客户端过滤；
  - 大数据集使用服务端搜索/索引；
  - 前端搜索库如 Fuse.js、MiniSearch、Lunr；
  - 服务端搜索引擎如 Elasticsearch / OpenSearch、Algolia、Meilisearch。
- 索引与倒排：大数据量避免每次输入全量遍历。
- 虚拟列表（Virtual List）：长结果列表只渲染可视区域。
- Web Worker（后台线程）：重客户端搜索可放入 Worker，避免阻塞主线程。
- 请求取消与缓存：`AbortController`、`requestId`、结果缓存、预取。
- 最小化重渲染：搜索状态拆分，避免输入导致整表重渲染。

## 十一、可观测性与测试

- 埋点分析（Analytics）：
  - 搜索提交、建议点击、零结果率、搜索延迟、结果点击率；
  - 快捷键使用率、清空率、定位跳转次数。
- A/B 测试：防抖时长、建议策略、结果排序、空状态文案。
- 单元测试：分词、规范化、防抖、高亮转义、结果计数。
- E2E（端到端）测试：键盘导航、IME 输入、请求竞态、清空重置、URL 同步。
- 可访问性测试：键盘全流程、屏幕阅读器播报、焦点管理。

## 十三、一句话原则

> 过滤模式（Filter Mode）管“数据变少”，定位模式（Find Mode）管“高亮跳转”，建议模式（Typeahead）管“预测选择”，命令面板（Command Palette）管“快捷执行”；四者共享输入框，但状态、键盘语义与结果展示应分别设计。
