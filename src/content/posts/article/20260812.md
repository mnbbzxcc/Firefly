## n8n表单服务ipv6公网部署

### 一、网络与域名准备

#### 1.确认ipv6支持

> 本机需有公网ipv6地址（ipconfig 查看，以`240e:`/`2408:`/`2001:`开头，确保可以被外部访问，部分宽带厂商即使ipv6也是nat代理导致无法公网访问）

#### 2.Cloudflare 域名准备

>  主域名：`303009.xyz`（已托管在 Cloudflare）
>
> 子域名：`n8n.303009.xyz`（用于访问 n8n）
>
> DNS 记录类型：`AAAA`（ipv6）
>
> 代理状态：`仅DNS`（灰色云朵，不开启代理）

### 二、n8n Docker配置

首先n8n要能够用ipv6地址来进行访问

> 目的就是为了让docker容器的n8n服务可以被远程访问，现在个人基本都分配不到公网ipv4地址，只能选择使用公网ipv6地址

docker-compose.yml个人配置

```yaml
services:
  n8n:
    image: docker.n8n.io/n8nio/n8n
    container_name: youzhilu-n8n
    restart: unless-stopped
    ports:
      # 让n8n同时监听ipv6流量
      - "[::]:${N8N_PORT:-5678}:5678"
    environment:
      # 时区配置，选择东八区UTC+8工作流更符合国内使用习惯
      - TZ=Asia/Shanghai 
      - GENERIC_TIMEZONE=Asia/Shanghai
      - N8N_SECURE_COOKIE=false
      # 工作流里用 {{ $env.WECOM_WEBHOOK }} 发企业微信群机器人消息
      - WECOM_WEBHOOK=${WECOM_WEBHOOK:-}
      # n8n 2.x默认封禁节点内 $env 访问，需显式放开
      - N8N_BLOCK_ENV_ACCESS_IN_NODE=false
    volumes:
      - n8n_data:/home/node/.n8n
    networks: [yz]
    
volumes:
  n8n_data:

networks:
  yz:
```

### 三、DDNS 配置（ddns-go）

方案选择：最终采用windows宿主机直接运行，Docker环境下ddns-go疑似存在网络兼容性问题：

- `bridge`模式：容器无法获取宿主机公网 ipv6

- `host`模式：windows+wsl2疑似存在端口绑定兼容问题

#### 1.安装ddns-go

> 这是一个动态域名解析的服务，之所以需要动态域名解析，是因为现在ipv6地址并没有固定分配，频繁更换

[GitHub地址](https://github.com/jeessy2/ddns-go/releases)

版本：ddns-go_6.17.5_windows_x86_64

> 这是截止至2026/08/12最新版

#### 2.使用ddns-go

- 不安装使用

  > 双击`ddns-go.exe`即可使用，但是需要一直挂着终端窗口

- 安装使用（配置后可以始终后台运行）
  必须以管理员身份运行终端（cmd/powershell），不然会因为权限问题安装不成功

  ```bash
  # 进入对应目录后使用命令安装
  ddns-go.exe -s install
  ```

#### 3.配置 ddns-go

访问ddns的web界面：http://localhost:9876

- DNS 服务商：Cloudflare

- API Token：使用 Cloudflare 创建的专用 Token（权限：Zone - DNS - Edit，区域资源：303009.xyz）

- ipv6 获取方式：通过接口获取（如 https://v6.ident.me）

- 域名：`n8n.303009.xyz`

- 记录类型：AAAA

#### 4.验证 DDNS 状态

```bash
nslookup n8n.303009.xyz 8.8.8.8预期返回本机公网ipv6地址。
```

### 四、windows 防火墙配置

#### 1.放行 5678 端口（允许所有 IP 访问）

以管理员身份运行 CMD：

```cmd
netsh advfirewall firewall add rule name="n8n-5678" dir=in action=allow protocol=TCP localport=5678
```

#### 2.查看已创建的规则

```cmd
netsh advfirewall firewall show rule name="n8n-5678"
```

#### 3.如需删除规则

```cmd
netsh advfirewall firewall delete rule name="n8n-5678"
```

### 五、Cloudflare API Token 创建记录

- Token 配置
  名称：n8n-ddns

- 权限：

  - Zone - DNS - Edit

  - Zone - Zone - Read

  - 区域资源：Include → Specific zone → 303009.xyz

- 客户端IP过滤：留空（本机无公网 IPv4，无法使用）


> [!CAUTION]
>
> Token 权限最小粒度为整个域名（Zone），无法单独限制到子域名。

### 六、验证流程

#### 1.检查 DDNS 是否生效

```bash
nslookup n8n.303009.xyz 8.8.8.8
```

#### 6.2 检查连通性

cmd
ping -6 n8n.303009.xyz

#### 6.3 浏览器访问

本机：http://n8n.303009.xyz:5678

手机流量测试：关闭 WiFi，用手机流量访问同一地址

#### 6.4 获取表单 Production URL

n8n 工作流 → Form Trigger 节点 → 切换到 Production URL

复制链接发给同事：http://n8n.303009.xyz:5678/form/xxxxxxxxxxxxxxxx

### 七、注意事项

事项	说明
Cloudflare 代理	必须关闭（灰色云朵），否则ipv6回源可能失败
ipv6 网络要求	访问者（同事）的网络也需要支持 ipv6
防火墙安全	如需限制访问 IP，可在防火墙规则中设置作用域
端口号	目前使用 :5678，后续迁移到云服务器可配置 Nginx 去掉端口
DDNS 服务管理	卸载服务：ddns-go.exe -s uninstall

### 九、常见问题记录

Q1：ddns-go 报错 Root domain not found
原因：主域名填写错误（如 .com vs .xyz）

解决：确认 Cloudflare 上的主域名，在 ddns-go 中使用完整域名 n8n.主域名

Q2：ddns-go 报错 cannot derive eTLD+1 for domain "n8n"
原因：域名列表只填了子域名，未填完整域名

解决：改为完整域名 n8n.303009.xyz

Q3：Docker 下 ddns-go 无法获取 ipv6
原因：bridge 模式容器网络隔离；host 模式在 windows wsl2 下有兼容问题

解决：放弃 Docker，直接在宿主机运行 ddns-go

Q4：n8n Form Trigger 的 Production URL 显示 localhost
原因：未设置 WEBHOOK_URL 环境变量

解决：在 n8n 容器环境变量中添加 WEBHOOK_URL=http://n8n.303009.xyz:5678/
