## 最简单的ipv6公网访问


### 一、网络与域名准备

#### 1.确认ipv6支持

> ```powershell
> # 查看本机的ip地址
> ipconfig -all
> ```
>
> - 本机需有公网ipv6地址（以`240e:`/`2408:`/`2001:`开头，确保可以被外部访问，部分宽带厂商即使ipv6也是nat代理导致无法公网访问）
>
> - 如果实在没有公网ipv6地址，可以连接手机热点，基本可以解决
>
>   > 即使手机热点其ipv6也有可能是nat代理导致无法公网访问，此处点名联通，联通大概率入站全拦截（海南联通已验证全拦截）

#### 2.cloudflare托管域名准备

示例：

> 主域名：`example.test`（托管在Cloudflare）
>
> 子域名：`web.example.test`（用于访问web项目）
>
> DNS记录类型：`AAAA`（ipv6）
>
> 代理状态：`仅DNS`（灰色云朵，不开启代理）

> [!NOTE]
>
> 使用自己的域名（本次的`example.test`只是示例，后文的所有域名请自行更换），不建议使用主域名，可以像我一样使用自己的子域名

### 二、极简web项目配置

#### 1.创建项目

**目录结构**如下：

```
web
├─ app/
│  └─ main.py
├─ .env
├─ docker-compose.yml
├─ Dockerfile
└─ requirements.txt
```

`main.py`

```python
from datetime import datetime

from fastapi import FastAPI
from fastapi.responses import HTMLResponse

app = FastAPI()


@app.get("/", response_class=HTMLResponse)
def home():
    now = datetime.now().strftime("%Y-%m-%d %H:%M:%S")
    return f"<h1>Hello,World!</h1><p>当前服务器UTC时间：{now}</p>"
```

`.env`环境变量

> [!NOTE]
>
> 这种方式比较灵活
>
> - 避免了硬编码（git版本控制时安全性高）
> - 可以轻松做到替换不同的`.env`文件来做到从开发环境切换到生产环境的移植
> - 跨平台语言通用（KAY=VAL）
> - 可以轻松使用`.env.example`来完成团队的隐形契约
> - 系统环境变量优先级高于`.env`文件，让其更好的作为兜底

```properties
# FastAPI端口
FASTAPI_PORT=8000
```

> `.env`文件本质是纯文本键值对，使用`properties`高亮仅为便于阅读，实际并无固定后缀语法。

`docker-compose.yml`

```yaml
services:
  fastapi:
    build: .
    container_name: fastapi
    restart: unless-stopped
    ports:
      - "${FASTAPI_PORT:-}:8000"
    volumes:
      - ./app:/app
    command: uvicorn main:app --host 0.0.0.0 --port 8000 --reload
    networks: [test]

networks:
  test:
```

`Dockerfile`

```dockerfile
FROM python:3.12-slim

WORKDIR /app

COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY app/ .

EXPOSE 8000

CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]
```

`requirements.txt`

```
fastapi
uvicorn[standard]
```

#### 2.启动项目

进入相应的web目录

```bash
docker compose up -d --build
```



### 三、ddns配置（ddns-go）

方案选择：最终采用windows宿主机直接运行

> docker desktop环境下不支持--net=host（host网络模式），该模式下容器才能与宿主机共享网络线从而读取网卡信息。在windows上使用默认桥接模式时，容器处于独立网络命名空间，无法看到宿主机ipv6地址

- `bridge`模式：容器无法获取宿主机公网ipv6

- `host`模式：windows+wsl2疑似存在端口绑定兼容问题

#### 1.安装ddns-go

> 这是一个动态域名解析的服务，之所以需要动态域名解析，是因为现在ipv6地址并没有固定分配，运营商会对其频繁更换，原因有下：
>
> - 设备主动
>
>   - ipv6隐私扩展
>   - 避免基于mac地址的追踪
>   - 移动网络下变更更频繁
>
> - 运营商策略
>
>   - 动态分配前缀
>
>     > 通常采用前缀委托的方式，动态分配一个地址段（即为前缀），设备重新拨号或者断线重连都有可能变化
>
>   - 运营商的商业考量
>
>     > 降低管理成本：维持海量绑定关系增加系统开销
>     >
>     > 限制自建服务：阻止用户轻易搭建对外的web服务器或远程访问
>     >
>     > 便于网络管理：

[GitHub地址](https://github.com/jeessy2/ddns-go/releases)

版本：ddns-go_6.17.5_windows_x86_64

> 这是截止至2026/08/12最新版，选择当前的最新版即可

#### 2.使用ddns-go

- 不安装使用

  > 双击`ddns-go.exe`即可使用，但是需要一直挂着终端窗口

- 安装使用（配置后可以始终后台运行）
  必须以管理员身份运行终端（cmd/powershell），不然会因为权限问题安装不成功

  ```bash
  # 进入对应目录后使用命令安装
  ddns-go.exe -s install
  ```

#### 3.配置ddns-go

访问ddns的web界面：http://localhost:9876

- DNS服务商：Cloudflare
- API Token：使用Cloudflare创建的专用Token
- ipv6获取方式：通过网卡
- 域名：`web.example.test`

> [!NOTE]
>
> 配置文件存放位置：C:/Users/用户名/.ddns_go_config.yaml

#### 4.验证ddns状态

```bash
# 查看dns
nslookup web.example.test 8.8.8.8
```

预期返回内容示例

> 服务器: dns.google
> Address: 8.8.8.8
>
> 名称: web.example.test
> Address: 240e:xxxx:xxxx:xxxx:xxxx:xxxx:xxxx:xxxx

### 四、windows防火墙配置

#### 1.放行端口（允许所有IP访问）

以管理员身份运行CMD：

```cmd
netsh advfirewall firewall add rule name="web" dir=in action=allow protocol=TCP localport=8000
```

#### 2.查看已创建规则

```cmd
netsh advfirewall firewall show rule name="web"
```

#### 3.如需删除规则

```cmd
netsh advfirewall firewall delete rule name="web"
```

### 五、cloudflare api token创建

>  设置在：个人头像-profile-API Tokens

> 配置示例如下：（域名改为自己的）

- Token配置
  名称：web-ddns

- 权限：

  - Zone - DNS - Edit

  - Zone - Zone - Read

  - 区域资源：Include → Specific zone → example.test

- 客户端IP过滤：留空（本机无公网IPv4，无法使用）


> [!CAUTION]
>
> Token权限最小粒度为整个域名（Zone），无法单独限制到子域名。

### 六、验证流程

#### 1.检查ddns是否生效

```bash
nslookup web.example.test 8.8.8.8
```

#### 2.检查连通性

```cmd
ping -6 web.example.test
```

#### 3.浏览器访问

本机：http://web.example.test:8000

> 查看服务是否启动

手机流量测试：关闭WiFi，用手机流量访问同一地址

>  不使用同一个网络，才能测试公网访问是否连通

### 七、注意事项

| 事项           | 说明                                                    |
| -------------- | ------------------------------------------------------- |
| cloudflare代理 | 必须关闭（灰色云朵），否则ipv6回源可能失败              |
| ipv6网络要求   | 访问者（同事）的网络也需要支持ipv6                      |
| 防火墙安全     | 如需限制访问IP，可在防火墙规则中设置作用域              |
| 端口号         | 目前使用8000端口，后续迁移到云服务器可配置nginx去掉端口 |
| ddns服务管理   | 卸载服务：ddns-go.exe -s uninstall                      |

### 八、最终架构图

```
同事浏览器（支持ipv6）
         ↓
http://web.example.test:8000
         ↓
cloudflare dns（仅解析，不代理）
         ↓
本机公网ipv6（240e:xxxx:xxxx:xxxx:...）
         ↓
windows防火墙（放行8000端口）
         ↓
docker web容器（端口映射[::]:8000:8000）
```

### 九、常见问题记录

Q1：ddns-go报错Root domain not found
原因：主域名填写错误

解决：确认cloudflare上的主域名，在ddns-go中使用完整域名`web.example.test`

Q2：ddns-go报错cannot derive eTLD+1 for domain "web"
原因：域名列表填的子域名前缀，未填完整域名

解决：改为完整域名`web.example.test`

Q3：docker下ddns-go无法获取ipv6
原因：bridge模式容器网络隔离；host模式在windows wsl2下有兼容问题

解决：放弃Docker，直接在宿主机运行ddns-go
