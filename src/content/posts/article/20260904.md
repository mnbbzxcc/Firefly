## 内网穿透

### 前情提要

- 原设计：`移动热点ipv6` + `docker` + `ddns-go` + `nginx` + `acme-companion`
- 缺陷：移动热点获取可公网访问的ipv6较为不便，且ipv4-only设备无法访问

### frp下载

- [frp官方GitHub地址](**`https://github.com/fatedier/frp`**)

  > 按需下载最新版release即可，本次示例下载的`frp_0.71.0_linux_amd64.tar.gz`
  >
  > 另外最好自行下载好上传而不是直接在服务器拉取，速度将会非常慢

### 服务端配置

> 此方案需要一台**带宽较高**的云服务器，其他配置无要求
>
> 建议云服务器使用linux系统，运行更加稳定，本次教程使用的是ubuntu24.04

#### 生成两个强随机串

>  作为auth token和dashboard密码

```powershell
# windows中生成强随机串
-join ((48..57)+(65..90)+(97..122) | Get-Random -Count 32 | ForEach-Object {[char]$_})
```

#### 编写`frps.toml`

```toml
# frps 服务端配置 —— 跑在小服务器上
# 文档：https://github.com/fatedier/frp（配置参考 examples 里的 frps.toml）

# frp 控制端口：frpc 从家里连过来的入口
bindPort = 7000

# 认证令牌（换成刚生成的强随机串）
auth.token = "qwert"

# 管理面板（可选但强烈建议，排查隧道状态很方便）
# 只监听服务器本机回环，要用 FinalShell 的隧道功能或 SSH 端口转发才能看到
webServer.addr = "127.0.0.1"
webServer.port = 7500
webServer.user = "admin"
webServer.password = "yuiop"

# 客户端与服务器之间的连接保持探测（家里路由器常掐空闲长连接）
transport.heartbeatTimeout = 90
```

> 示例使用的认证令牌和dashboard密码仅作参考，实际过程中尽量选择**强密码**

#### 端口放行

打开服务器控制台的防火墙配置，确保放行以下端口（均选择TCP即可）：

- 22（用于ssh连接）

- 80（用于http访问和证书续签验证）
- 443（用于https访问）
- 7000（用于frp隧道）

#### finalshell剩余配置

```bash
# 创建文件夹
mkdir -p /opt/frp
# 赋权
chmod +x /opt/frp/frps
# 试跑验证
./frps -c frps.toml

# 验证无误后写systemd服务（为了开机自启+崩溃自动拉起）
touch /etc/systemd/system/frps.service
```

编写`frps.service`的内容

```
[Unit]
Description=frp server (frps)
After=network.target

[Service]
Type=simple
ExecStart=/opt/frp/frps -c /opt/frp/frps.toml
Restart=always
RestartSec=5
LimitNOFILE=1048576

[Install]
WantedBy=multi-user.target
```

```bash
# 重新加载系统服务配置
sudo systemctl daemon-reload
# 启用并立即启动服务
sudo systemctl enable --now frps
# 查看运行服务状态
sudo systemctl status frps
```

> [!NOTE]
>
> v0.71.0版本frps默认支持TLS加密，客户端单方面开启即可，服务端无需配置和重启

### 客户端配置

项目根目录/frp/

`frpc.toml`编写fprc配置

```toml
# frpc 客户端配置 —— 跑在 Windows 的 docker 里
# 隧道：frpc --(出站长连接)--> 服务器 frps，把服务器的 80/443 转发到本栈 nginx-proxy

# 服务器公网 IP 和 frps 的 bindPort
serverAddr = "xxx.xxx.xxx.xxx"
serverPort = 7000

# 与 frps.toml 里一致的 token
auth.token = "qZWe5AwLhIDkdU9imzT34O6Yyu0K1GCQ"

# 到 frps 的连接启用 TLS（多一层加密，顺手开掉）
transport.tls.enable = true

# 两条整体穿透代理：服务器端口 -> 容器网络里的 nginx-proxy
# localIP 用容器名直连（同 rag / backup-dl 的反代模式），frpc 和 nginx-proxy 同在 auto 网络

[[proxies]]
name = "web-http"
type = "tcp"
localIP = "nginx-proxy"
localPort = 80
remotePort = 80

[[proxies]]
name = "web-https"
type = "tcp"
localIP = "nginx-proxy"
localPort = 443
remotePort = 443
```

>  示例所写的公网ip写的是xxx.xxx.xxx.xxx，实际应该换成真实的服务器ip

`docker-compose.yml`增加frpc服务

```yaml
frpc:
  image: fatedier/frpc:v0.71.0
  container_name: frpc
  restart: unless-stopped
  command: ["-c", "/etc/frp/frpc.toml"]   # 必须！镜像默认入口找 ./frpc.ini 会报错
  volumes:
    - ./frp/frpc.toml:/etc/frp/frpc.toml:ro
  networks: [auto]
```

> **勿设 VIRTUAL_HOST/LOCATION**

### DNS切换

打开cloudflare域名托管的dns记录，把原本的AAAA记录更改为A记录，并且更换为真实的服务器ip

### 管理面板访问

frps dashboard只绑定了服务器`127.0.0.1:7500`，让其走finalshell ssh隧道，进而远程连接的时候可以本地访问到管理面板

连接属性--隧道--本地转发7500--浏览器打开[127.0.0.1:7500](http://127.0.0.1)

> 账号密码在`frps.toml`的webserver段

### 服务器到期后退回原方案

接续使用ddns-go完成dns解析，然后在docker compose文件注释frpc服务即可
