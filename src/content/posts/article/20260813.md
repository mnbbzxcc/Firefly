## 反向代理+证书管理

### 一、准备工作

#### 1.前情提要

- [x] web项目已正常运行，且可被外网访问
- [x] ddns-go正常完成动态域名解析

#### 2.移除无效规则

```bash
netsh advfirewall firewall delete rule name="web"
```

> 已经准备使用反向代理了，就不直接暴露8000端口到公网了

#### 3.给nginx服务添加入站规则

需要使用**管理员**终端

```bash
# 放行80端口
netsh advfirewall firewall add rule name="web-nginx-http" dir=in action=allow protocol=TCP localport=80
# 放行443端口
netsh advfirewall firewall add rule name="web-nginx-https" dir=in action=allow protocol=TCP localport=443
```

#### 4.获取令牌

获取cloudflare的api token令牌，用于后续的自动申领证书

>  设置在：个人头像-profile-API Tokens

> 配置示例如下：（域名改为自己的）

- Token配置
  名称：acme-dns-challenge

- 权限：

  - Zone - DNS - Edit

  - Zone - Zone - Read

  - 区域资源：Include → Specific zone → example.test

- 客户端IP过滤：留空（本机无公网IPv4，无法使用）


> [!CAUTION]
>
> Token权限最小粒度为整个域名（Zone），无法单独限制到子域名。
> 生成的Token字符串是一次性的，自行复制并妥善保管

> 和之前ddns-go使用的api token区分，便于个人控制

#### 5.证书申领知识拓展

**DNS-01**和**HTTP-01**是两种不同的ACME验证方式

（1）核心区别

| 对比维度             | DNS-01                                                       | HTTP-01                                                      |
| :------------------- | :----------------------------------------------------------- | :----------------------------------------------------------- |
| 验证原理             | 在`_acme-challenge.example.test`添加一条TXT记录，CA查询DNS验证 | 在`http://example.test/.well-known/acme-challenge/xxx`放置验证文件，CA访问验证 |
| 是否支持通配符证书   | ✅支持，且是唯一支持通配符的方式                              | ❌不支持                                                      |
| 是否需要公网入站端口 | 不需要                                                       | 通常需要**80端口**对公网开放                                 |
| 是否需要公网IP       | 不需要，申请机器可在内网                                     | 通常需要，或至少有公网入口映射到该机器                       |
| 自动化依赖           | 需要DNS服务商API，或手动添加TXT记录                          | 需要Web服务器可写目录，或临时监听80端口                      |
| CDN/反向代理影响     | 基本不受HTTP层影响，只查DNS                                  | 容易受CDN、重定向、缓存、防火墙影响                          |
| 内网机器申请         | ✅适合                                                        | ❌不适合，除非有公网端口映射                                  |
| 多域名支持           | 支持，每个域名加TXT记录                                      | 支持，每个域名都要能访问验证文件                             |
| 验证速度             | 取决于DNS传播，可能几十秒到几分钟                            | 通常较快，配置正确时很快                                     |
| 安全关注点           | DNS API Token权限必须最小化                                  | 80端口、Web目录权限、重定向规则                              |
| 常见失败原因         | TXT未生效、API权限不足、记录冲突、DNS商不支持                | 80端口不通、重定向错误、CDN拦截、Web根目录错误               |
| acme.sh示例          | `acme.sh --issue --dns dns_cf -d example.com -d '*.example.com'` | `acme.sh --issue -d example.com -w /var/www/html` 或 `--standalone` |
| 颁发证书类型         | DV证书                                                       | DV证书，信任级别相同                                         |

（2）优劣势和使用场景

| 类型    | 优势                                                         | 劣势                                                         |
| :------ | :----------------------------------------------------------- | :----------------------------------------------------------- |
| DNS-01  | 支持泛域名；不需要公网80端口；适合内网、CDN后、多服务器；续期不依赖Web服务 | 需要DNS API凭证，泄露风险较高；需等待DNS传播；部分DNS商不支持API；配置稍复杂 |
| HTTP-01 | 配置直观；不需要DNS API；验证通常较快；适合普通单域名网站    | 不支持泛域名；需要80端口公网可达；CDN、重定向、防火墙容易干扰；多服务器和内网场景麻烦 |

 （3）使用场景

| 类型    | 典型适用场景                                                 |
| ------- | ------------------------------------------------------------ |
| DNS-01  | 申请`*.example.com`；服务器无公网IP；Cloudflare橙云代理；多台服务器共用一张证书；不想暴露80端口 |
| HTTP-01 | 单域名普通网站；服务器直接暴露80端口；不想管理DNS API；简单快速签发 |

### 二、配置更改

#### 1.目录结构

```
web
├─ app/
│  └─ main.py
├── proxy/
│  ├─ acme-sh/                 acme-companion的acme.sh状态（账户+证书登记，持久化防重签）
│  ├─ certs/                   域名证书的放置目录
│  ├─ html/                    nginx和acme-companion的共享web目录，用于互联验证
│  └─ vhost/                   nginx站点配置文件的挂载目录
├── .env
├── docker-compose.yml
├── Dockerfile
└── requirements.txt
```

#### 2.`.env`文件

```properties
# FastAPI端口
FASTAPI_PORT=8000
# 域名
WEB_DOMAIN=web.example.test
# Let's Encrypt证书通知邮箱
DEFAULT_EMAIL=test@example.test
# cloudflare的api token，用于dns api申领证书
CF_TOKEN=cfut_xxx
```

> - 域名用于访问，web.example.test域名仅为示例，更换为自己真实的域名
> - 邮箱用于通知证书过期，test@example.test邮箱仅为示例，更换为自己真实的邮箱
> - api token令牌用于更方便地申领证书，cfut_xxx令牌仅为示例，更换为自己真实的令牌

#### 3.`docker-compose.yml`

```yaml
services:
  fastapi:
    build: .
    container_name: fastapi
    restart: unless-stopped
    volumes:
      - ./app:/app
    command: uvicorn main:app --host 0.0.0.0 --port 8000 --reload
    environment:
      - ACME_CHALLENGE=DNS-01
      - VIRTUAL_HOST=${WEB_DOMAIN}
      - VIRTUAL_PORT=${FASTAPI_PORT}
      - LETSENCRYPT_HOST=${WEB_DOMAIN}
      - LETSENCRYPT_EMAIL=${DEFAULT_EMAIL}
    networks: [test]

  nginx-proxy:
    image: nginxproxy/nginx-proxy
    container_name: nginx-proxy
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./proxy/html:/usr/share/nginx/html
      - ./proxy/certs:/etc/nginx/certs
      - ./proxy/vhost:/etc/nginx/vhost.d
      - /var/run/docker.sock:/tmp/docker.sock:ro
    labels:
    - "com.github.nginx-proxy.nginx=true"
    networks: [test]

  acme-companion:
    image: nginxproxy/acme-companion
    container_name: acme-companion
    restart: unless-stopped
    volumes:
      - ./proxy/html:/usr/share/nginx/html
      - ./proxy/certs:/etc/nginx/certs
      - ./proxy/vhost:/etc/nginx/vhost.d
      - ./proxy/acme-sh:/etc/acme.sh
      - /var/run/docker.sock:/var/run/docker.sock:ro
    environment:
      - DEFAULT_EMAIL=${DEFAULT_EMAIL}
      - "ACMESH_DNS_API_CONFIG={DNS_API: 'dns_cf', CF_Token: '${CF_TOKEN}'}"
    networks: [test]
    depends_on:
      - nginx-proxy

networks:
  test:
```

> [!NOTE]
>
> - 新增nginx-proxy和acme-companion两个容器
> - fastapi容器去除端口映射，不再使用直接暴露8000端口的方式发布至公网
> - fastapi容器申领Let's Encrypt证书选择了DNS-01而非HTTP-01
> - fastapi容器**必须**新增所示环境变量才能完成申领证书流程

### 三、启动服务

```bash
docker-compose up -d --build
```

### 四、验证

#### 1.查看日志

```bash
docker logs acme-companion   # 应显示证书签发成功
docker logs nginx-proxy      # 应无报错
```

#### 2.浏览器访问

访问`https://web.example.test`，地址栏应显示安全锁标志，且能正常显示内容。

### 五、架构总结

```
同事浏览器
    ↓
https://web.example.test
    ↓
Cloudflare DNS（仅解析，不代理）
    ↓
Windows防火墙（放行80/443）
    ↓
nginx-proxy（监听80/443，自动申请SSL）
    ↓
web容器（内网8000端口，不对外暴露）
    ↓
Form Trigger → 处理上传 → 钉钉消息
```
